# TokenWise website

The landing page and all TokenWise documentation, built with Astro and Starlight and deployed to GitHub Pages by `.github/workflows/pages.yml`.

## Commands

From the repository root (Node.js 26+, pnpm 9):

```bash
pnpm install
pnpm build                          # the CLI; the generators and demo capture use it
pnpm --filter website dev           # http://localhost:4321 with live reload
pnpm --filter website build         # generate references, capture demo output, build dist/
pnpm --filter website check         # docs accuracy + built-site checks (links, sitemap, privacy, JS budget)
pnpm --filter website check:external  # also fetch external links (network)
pnpm --filter website lighthouse    # Lighthouse CI, every category ≥ 0.95 (needs Chrome/Chromium; set CHROME_PATH)
pnpm --filter website assets        # re-render og.png and PNG favicons from SVG (commit the output)
```

`pnpm site` at the root runs the CLI build, the site build and the checks in one go.

All Astro commands go through `scripts/astro.ts`, which disables Astro's anonymous usage telemetry. If you change the Expressive Code or Markdown plugins and do not see the effect, delete `website/.astro` and `website/node_modules/.astro` (rendered Markdown is cached there).

## Where things come from

| Content | Source | Generated by |
|---|---|---|
| `docs/reference/cli` | Commander definitions in `apps/cli/src/` | `scripts/generate.ts` |
| `docs/reference/rules` | Rule registry (`packages/core/src/rules/`) and rule fixtures (`tests/fixtures/rules/`) | `scripts/generate.ts` |
| `docs/reference/config-schema`, `public/schemas/config.schema.json` | `ConfigSchema` in `packages/shared/src/schemas.ts` | `scripts/generate.ts` |
| `docs/reference/report-format`, `public/schemas/report.schema.json` | `ReportSchema` in `packages/core/src/report.ts` | `scripts/generate.ts` |
| `docs/changelog` | `CHANGELOG.md` | `scripts/generate.ts` |
| Landing-page terminal output, `public/demo/sample-report.html` | The built CLI run on `examples/sample-project` | `scripts/capture-demo.ts` |
| Everything else in `src/content/docs/docs/` | Written by hand | |

Generated files are gitignored and rebuilt on every build; a generator error fails the build. The npm package name and version shown on the site come from `apps/cli/package.json`. When the package is published, set `PUBLISHED_ON_NPM = true` in `src/data/release.ts` to drop the pre-release notes.

Write links between docs pages as relative paths ending in `/` (`../quickstart/`), never with a leading `/`, so they work under any base path. `check-site.ts` fails on any link that does not resolve.

## URL and base path

The URL is set in exactly one place, `site.config.mjs`, from environment variables:

| Variable | Meaning | Default |
|---|---|---|
| `SITE_URL` | Origin, e.g. `https://owner.github.io` or `https://tokenwise.dev` | `http://localhost:4321` |
| `BASE_PATH` | Path prefix, e.g. `/tokenwise/` or `/` | `/` |
| `REPO_URL` | GitHub repository for "View on GitHub" and "Edit page" links (omitted when unset) | unset |
| `REPO_BRANCH` | Branch for edit links | `main` |

In CI, the deploy job reads `SITE_URL` and `BASE_PATH` from the repository's Pages settings (`actions/configure-pages`), and `REPO_URL` from the repository itself. Pull requests build under `https://example.github.io` + `/tokenwise/` so that base-path bugs fail the checks.

The three hosting options need no code change:

| Option | URL | What to configure |
|---|---|---|
| Project site (default) | `https://<owner>.github.io/<repo>/` | Nothing beyond enabling Pages. |
| User or organization site | `https://<name>.github.io/` | The repository must be named `<name>.github.io` and owned by the user or organization `<name>`. |
| Custom domain | `https://tokenwise.dev/` | Set the domain in Settings → Pages and create the DNS records below. No `CNAME` file is needed: with a GitHub Actions workflow, GitHub ignores it. |

## One-time setup for the maintainer

These are repository settings; the workflow cannot change them.

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. If the default branch is not `main`, change `branches: [main]` in `.github/workflows/pages.yml`.
3. Optional, custom domain: Settings → Pages → Custom domain, then at your DNS provider either
   - for an apex domain (`tokenwise.dev`): `A` records to `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (and `AAAA` records to `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`), or
   - for a subdomain (`docs.example.com`): a `CNAME` record to `<owner>.github.io`.

   Then enable "Enforce HTTPS". The next deploy picks up the new origin from `actions/configure-pages`. Verifying the domain for your account or organization (Settings → Pages → Verified domains) protects it from takeover.
4. Once the site URL is known, set `"homepage"` in `apps/cli/package.json` to it (e.g. `https://<owner>.github.io/tokenwise/`). The CLI then prints a link to each rule's documentation in `tokenwise audit` output.

## Privacy

The site loads nothing from third parties: no analytics, cookies, tracking pixels, web fonts or CDN scripts. `check-site.ts` fails the build if the output references any. Search is Pagefind's static index, loaded from the site itself when the search box is opened. The theme choice is kept in the browser's local storage by Starlight.
